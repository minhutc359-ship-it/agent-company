# 2.5 · Guided Workspace, agent connections and managed updates

PM/QC users previously had to understand model routes and find Owner controls across several tabs. This release adds a persistent next-step card, anchored idle guidance and a direct agent connection form. Published installations also gain an in-app update flow instead of manual ZIP replacement.

## Delivered behavior

- **Kết nối AI** selects an employee, Claude API / OpenAI API / Gemini API / Claude Code, model and API key. Account model discovery is an explicit key-only request. Connection consent enables Controlled Cloud; keys stay in RAM, never in event history, UI responses or backups. Re-entering a key for an unchanged route preserves provider/configuration versions so pinned runs can continue after restart.
- BA/Leader/Dev can use pinned cloud routes inside the existing software workflow. Each actual payload requires an exact preview and Owner approval before dispatch. Current provider/policy, lease, payload hash, token cap and source classification are rechecked; progressive file requests require fresh approval. Typed artifacts/patches still pass the existing validators, scoped worktree grants, Docker checks and final Owner gates. Strict Local remains the default and blocks dispatch.
- Claude Code is a separate CLI engine for Anthropic keys: explicit installed executable fingerprint, bare/restricted noninteractive session, no built-in or MCP tools, no session persistence, isolated temporary working/config/home directory, bounded output/time/turns and an SDK spend estimate cap. It returns structured proposals; the runtime executes approved patches/tests. It does not reuse subscription/OAuth logins, run arbitrary CLI commands, grant tools or mount a project. Other external CLIs retain reviewed handoff/import.
- **Bước tiếp theo** names the current Owner decision and opens the actual action: demo, task, cloud preview, scope, retry/recovery, acceptance or source download. Workflow node labels and tabs use plain Vietnamese. The office remains visible without a row of redundant metrics pushing it down.
- After 15 seconds without pointer, keyboard, wheel or touch activity, a dismissible tip anchors to the relevant action. It does not steal focus, scroll automatically, approve anything or interrupt text entry, open dialogs or background tabs. Users can disable it; the preference survives reload. Realtime refresh retains guidance without resetting the idle clock.
- **Cập nhật ứng dụng** checks the repository's stable GitHub Release, downloads only its bounded HTTPS asset, verifies the GitHub SHA256 digest plus every extracted file, rejects unsafe archives, and stages a versioned application. Applying fences new writes and requires all model/container work to be stopped. The launcher closes the old runtime, snapshots the complete data directory, switches the application pointer, restarts and verifies the expected build through the real health endpoint. Startup failure restores both the previous pointer and closed-store snapshot, retaining failed data for investigation. Models and source repositories outside the managed data directory are not moved or replaced.
- CI publishes immutable `build-<run number>` stable releases only after a **master push** passes Linux, Windows and Chromium jobs. Feature branches/PRs produce downloadable setup artifacts but do not publish stable releases. Runtime .NET 10 / updater protocol 1 is enforced; an incompatible future major requires a new bootstrap installer.
- The source launcher `python setup/setup-aicos.py --source --launch --cloud-only` publishes current checked-out source and launches it with update supervision; it clears an old downloaded-version pointer so fresh source is actually used. Cloud-only setup skips mandatory Ollama/model installation; local routes remain optional.

## Validation

File/SQLite domain acceptance covers cloud route pins, exact consent, typed continuation, Strict Local fencing, secret-free history, maintenance and a real CLI subprocess protocol fixture. Python tests cover immutable metadata, download hashes, archive traversal/links/case/device names, staging, closed-store backup, healthy activation and rollback. A separate integration test starts the actual published .NET application, calls its update API, verifies a healthy managed restart, then deliberately attempts an invalid runtime and verifies automatic rollback with SQLite, demo, configurations, user files and model bytes preserved. CI runs that integration on Windows and Linux. Chromium covers the connection wizard, pending-cloud next step, fifteen-second tooltip/focus behavior, dismissal, update dialog states, existing software/Docker stories and mobile layout.

Live API accounts and installed Claude model behavior are not certified by fixtures. Keys/quota and model permissions need a target-account run. Vendor installation/UAC/WSL2 and GPU/CPU capacity remain host-specific. The setup is an online, unsigned distribution; HTTPS release digests detect altered bytes but are not publisher code-signing certificates. API keys must be re-entered after restart unless a separately managed environment reference is used. Source checkouts started directly with `dotnet run` do not have a supervisor; their update screen explains the managed launcher requirement.
